# MySQL (mysqldump) to PostgreSQL (`MySQL-To-PGSQL.mog`)

Converts a `mysqldump` table-DDL export into PostgreSQL DDL. Like the MSSQL
converter it is a text/regex pipeline, not a SQL parser: it handles the common,
mechanical parts and documents the rest. It composes a reusable stripper,
`mysql-strip-dump-noise.mog`, that removes the dump scaffolding, then rewrites
what remains.

## Usage

```bash
mog -m MySQL-To-PGSQL.mog < dump.sql > schema.pgsql
```

`mysqldump` output is UTF-8, so no encoding flag is needed. Worked example:
this recipe's `tests/input.sql` converts to the committed `tests/expected.pgsql`
golden; a golden test (`mog-rs/tests/mysql_pgsql.rs`) guards it. The output parses as PostgreSQL (sqlglot) and **executes on PostgreSQL 16**,
all four tables and eight hoisted indexes are created, apart from one generated
column whose expression must be made immutable (see below).

## What it converts

| MySQL | PostgreSQL | Notes |
| --- | --- | --- |
| `` `name` `` backtick quoting | `name` | removed |
| `) ENGINE=InnoDB AUTO_INCREMENT=N DEFAULT CHARSET=... COLLATE=... COMMENT=...` | `)` | table options dropped |
| `col ... AUTO_INCREMENT` | `col ... GENERATED BY DEFAULT AS IDENTITY` | |
| `int unsigned`, `bigint unsigned`, ... | `int`, `bigint`, ... | `unsigned` dropped; see range note |
| `tinyint(1)` | `boolean` | 0/1 defaults left as `'0'`/`'1'` (PG casts) |
| `tinyint` | `smallint` | |
| `mediumtext` / `longtext` / `tinytext` | `text` | |
| `blob` / `mediumblob` / `longblob` / `tinyblob` | `bytea` | |
| `double` | `double precision` | |
| `datetime` | `timestamp` | |
| `json` | `jsonb` | |
| `enum('a','b')` | `varchar CHECK (col IN ('a','b'))` | inline; column name reused |
| `set('a','b')` | `text` | multi-value semantics lost, see below |
| `col ... GENERATED ALWAYS AS (expr) STORED` | same (backticks + `_utf8mb4` stripped) | **expr must be IMMUTABLE in PG**, see below |
| inline `KEY` / `UNIQUE KEY` / `FULLTEXT KEY` | `CREATE [UNIQUE] INDEX ... ON <table> (...)` | lifted out after the table (via `hoist_from_block`) |
| `CONSTRAINT fk FOREIGN KEY (...) REFERENCES ... ON DELETE/UPDATE ...` | same | kept inline (valid PG) |
| `ON UPDATE CURRENT_TIMESTAMP` | removed | needs a trigger, see below |

The dump scaffolding, `/*!NNNNN ... */` comments, `DELIMITER` blocks, `LOCK
TABLES` data blocks, view stubs/definitions, `SET`/`USE`/`CREATE DATABASE`/`DROP
TABLE`, is removed by the stripper.

## Not handled (do these by hand)

- **Views, stored routines, triggers, and data (`INSERT`s)** are **stripped**,
  not converted. MySQL routine/trigger bodies are a different language from
  PL/pgSQL; view bodies and data escaping would each be their own pass.
- **`unsigned` range.** Dropping `unsigned` widens the effective range: a MySQL
  `int unsigned` (to ~4.29e9) exceeds PG `integer`. For safety, widen the column
  (int -> bigint, bigint -> numeric(20)) or add a `CHECK (col >= 0)` by hand.
- **`ON UPDATE CURRENT_TIMESTAMP`** has no PG equivalent; recreate it with a
  `BEFORE UPDATE` trigger.
- **`FULLTEXT KEY`** becomes a plain b-tree `CREATE INDEX`, which is *not*
  full-text. Replace with a GIN index over a `tsvector` for real full-text search.
- **`SET('a','b')`** becomes `text`; the set-membership semantics are lost. Model
  it as a `text[]` with a `CHECK`, or a join table.
- **`ENUM`** becomes `varchar` + `CHECK`. If you prefer a native type, create a
  `CREATE TYPE ... AS ENUM (...)` and use it instead (a hoist the converter does
  not do by default).
- **`tinyint(1)` defaults.** The column becomes `boolean` but `DEFAULT '1'` /
  `'0'` are left as-is; PostgreSQL casts them (`'1'` -> true), which is usually
  fine, change to `true` / `false` if you want them explicit.
- **Generated-column immutability.** The `GENERATED ALWAYS AS (expr) STORED`
  syntax is kept, but PostgreSQL requires the expression to be `IMMUTABLE`, and
  several common MySQL functions are only `STABLE`. In particular
  `concat_ws(...)` and `concat(...)` are rejected with *"generation expression is
  not immutable"*; rewrite them with the `||` operator (e.g.
  `first_name || ' ' || last_name`), minding that `||` propagates `NULL` where
  `concat_ws` skips it. (Real-PostgreSQL execution catches this; a syntax check
  does not.) The converter **flags** each such column inline with
  `-- FIXME(mog): ...` and the CLI reports it, so you find it before loading
  rather than at load time.
- **Identifier case.** As with the MSSQL converter, PG lowercases unquoted
  identifiers; this script does not quote them.

## How it is built

- `mysql-strip-dump-noise.mog`, a reusable pass (composed via `run_mog`) that
  strips the mysqldump scaffolding.
- The main script then does backtick removal, type/identity/enum/set rewrites,
  and two `hoist_from_block` passes that lift inline indexes into standalone
  `CREATE INDEX` statements carrying the table name, the structural move a
  stateless pass otherwise cannot do.
